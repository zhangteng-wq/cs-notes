# cs-notes

计算机理论学习的笔记与代码归档。

记录自学计算机主干课程（算法 → 系统 → 应用）的全过程：每个知识点的理解笔记，以及亲手写的验证代码。

## 学习方式：三步闭环

每个「代码 / 算法类」知识点都按这三步走：

1. **教材主线** —— 以教材为准，理解概念、算法设计与实现思路，标注教材出处（书名 + 章节）。内容必须可在书本中溯源。
2. **GitHub 对照** —— 书本讲完后，去 GitHub 找公开项目里的真实实现，对照着再看一遍：看概念在真实约束下如何落地、教材写法与实际写法差在哪，以此巩固印象。
3. **归档** —— 把该知识点的笔记与亲手写的代码提交到本仓库对应目录。

## 目录约定

```
cs-notes/
├─ exercises/          碎片化学习代码
│  ├─ 算法/             按方向分类
│  │  └─ <知识点>/     每个知识点一个文件夹，内含笔记 README.md + 代码
│  ├─ 系统/
│  └─ 应用/
└─ projects/           完整项目代码
   └─ <项目名>/
```

### 为什么要区分 exercises 和 projects

两者虽然都是代码，但**生命周期完全不同**，混在一起会互相干扰：

| | exercises | projects |
|---|---|---|
| 规模 | 单文件为主，几十到几百行 | 多文件，有构建 / 依赖配置 |
| 目的 | 验证一个概念、做一道习题 | 能独立跑起来、会持续演进 |
| 生命周期 | 写完即归档，基本不再改 | 不断迭代，长期维护 |
| 例子 | 选择排序、生产者消费者、TCP 回显 | 课程大作业、Unity 游戏、完整小工具 |

### 笔记放在哪

笔记**跟随知识点，不单独集中存放** —— 每个知识点文件夹里的 `README.md` 就是它的笔记，和代码待在一起。这样以后翻某个主题，一眼能看到「当时怎么想的 + 代码长什么样」，不用在两处来回找。

## 命名与提交规范

- 知识点文件夹用中文名，如 `选择排序`、`生产者消费者问题`。
- 代码文件名用小写下划线，如 `selection_sort.c`、`producer_consumer.c`。
- 提交信息格式：`知识点名称（教材出处）`，例如 `选择排序（高级语言程序设计·第X章）`。
- 每个知识点的 `README.md` 建议包含：
  - 题目原文 / 要解决的问题
  - 宏观目的：这个东西到底解决什么问题
  - 核心思路与算法设计
  - 教材出处（书名 + 章节）
  - GitHub 对照心得：真实项目怎么写、差异在哪
  - 踩过的坑 / 易错点

## 注意

- 只提交源码与笔记，**不提交构建产物**（见 `.gitignore`）。
- 代码是拿来读和对比的，不直接复制第三方项目源码 —— 引用时注明来源与许可证。
